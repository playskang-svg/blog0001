# 블로그팁스 콘텐츠 운영안

## 사이트 콘셉트

블로그팁스는 일본 소도시의 교통 문제를 해결한 뒤 자연스럽게 숙박 거점 선택으로 이어지는 정보 사이트다.

글의 기본 흐름은 다음과 같다.

```text
공항·역·항구의 이동 문제
→ 도착 시각·짐·동행 조건별 교통수단 비교
→ 다음 날 이동을 고려한 숙박 권역 선택
→ 호텔·게스트하우스·단기임대 유형 비교
→ 지역과 정확히 일치하는 프로모션·예약 링크
```

교통 정보보다 예약 버튼이 먼저 나오지 않게 한다. 현재 지역과 일치하는 오퍼가 없으면 CTA를 숨기고 정보 글은 그대로 제공한다.

## 발행 폴더

`src/pages/posts/`는 글 파일을 넣는 폴더가 아니다. 실제 포스팅은 아래 폴더에 MD 또는 MDX로 저장한다.

```text
src/content/posts/published/
├── airport-to-stay/
├── no-car-small-city/
├── island-and-port/
├── stay-base/
└── late-arrival/
```

- 일반 글: `.md`
- `TravelPromotionEmbed`, `StayRecommendations`, Astro 이미지 컴포넌트를 쓰는 글: `.mdx`
- 기본 템플릿: `src/content/templates/travel-guide-template.mdx`
- 관리자 화면(`/admin`) 상단의 "글 파일 업로드" 버튼에 작성한 `.mdx`와 그 글의 이미지를 함께 넣으면
  `category`(frontmatter)와 파일명을 읽어 위 폴더와 `src/assets/images/posts/{category}/{slug}/`로 바로 커밋한다
- 폴더는 편집용 분류이며 공개 URL은 `/posts/{파일명}/` 형식으로 유지한다.
- 카테고리 노출은 파일 위치가 아니라 frontmatter의 `category` 값으로 결정한다.

## 이미지 폴더

```text
src/assets/images/posts/{category}/{post-slug}/
├── hero.webp
├── route-map.webp
└── stay-area.webp
```

래스터 이미지는 WebP만 허용한다. `npm run content:validate`가 JPG, JPEG, PNG, GIF, TIFF 참조를 발견하면 실패한다.

## 카테고리별 발행 대기열

### 1. 공항에서 숙소까지

1. 마쓰야마공항에서 도고온천 가는 법과 숙소 위치 선택 — 발행 완료 (`draft: false`)
2. 기타큐슈공항에서 고쿠라역 가는 법: 늦은 도착 숙소는 어디가 편할까 — 초안 작성 완료, 검토 대기 (`draft: true`, `kitakyushu-airport-to-kokura-stay.mdx`)
3. 다카마쓰공항에서 다카마쓰역·항구 이동: 나오시마 전날 숙소 위치 — 초안 작성 완료, 검토 대기 (`draft: true`, `takamatsu-airport-to-port-naoshima-stay.mdx`)
4. 사가공항에서 사가역·우레시노온천 이동: 당일 이동과 1박 비교 — 초안 작성 완료, 검토 대기 (`draft: true`, `saga-airport-to-station-ureshino-stay.mdx`; 우레시노온천 환승 구간은 출처 간 요금이 맞지 않아 단일 금액을 단정하지 않음 — 검토 시 확인 요망)

### 2. 렌터카 없는 소도시

1. 구마모토에서 아소산 차 없이 가는 법: 버스·투어와 1박 거점 비교 — 보류. 2026-08-14 화산경보 레벨3로 화구 반경 2km 규제·화구 셔틀버스 운행중단·아소산조터미널 일시폐쇄 이력 확인됨. 현재 규제 상태를 당일 [아소화산방재협의회](https://www.aso-volcano.jp/) 또는 [산코버스 화산규제 정보](https://www.sankobus.jp/site/aso/kisei/)에서 재확인한 뒤 작성할 것
2. 하카타에서 우레시노온천 대중교통 이동: 다케오온센 환승과 숙소 위치
3. 요나고공항에서 마쓰에 차 없이 이동: 첫날 숙박 거점 선택
4. 오이타공항에서 벳푸 이동: 공항버스 정류장별 숙소 권역 — 초안 작성 완료, 검토 대기 (`draft: true`, `oita-airport-to-beppu-stay.mdx`)

### 3. 섬·항구 환승

1. 다카마쓰항에서 나오시마 가는 법: 첫 배 전날 어디에 묵을까

## 지역 우선순위 근거

2026-09-22 네이버 검색광고 API의 PC·모바일 합산 참고치에서 다음과 같은 숙박 수요가 확인됐다.

| 지역 키워드 | 월간 검색 참고치 | 광고 경쟁 |
|---|---:|---|
| 마쓰야마 호텔 | 7,190 | 높음 |
| 마쓰야마 숙소 | 5,790 | 높음 |
| 다카마쓰 호텔 | 4,290 | 높음 |
| 기타큐슈 호텔 | 4,140 | 높음 |
| 기타큐슈 숙소 | 2,870 | 높음 |
| 구마모토 호텔 | 1,760 | 높음 |
| 나오시마 여행 | 2,050 | 높음 |

광고 경쟁도는 자연검색 난이도가 아니다. 호텔 키워드를 제목으로 정면 공략하지 않고, 검색량이 더 작은 공항·교통·환승 문제를 정확히 해결한 뒤 숙박 권역 판단으로 연결한다.

## Travelpromotion 연결

`src/data/affiliate-catalog.ts`에서 프로모션과 숙소 오퍼를 중앙 관리한다.

- 현재 활성 placement: `japan-promotion-general`
- 연결 페이지: `https://travelpromotion.tipspedia.kr/japan/`
- 글 안에서 카드로 연결: `<TravelPromotionEmbed placementKey="japan-promotion-general" />`
- 실제 페이지 임베드가 필요할 때만 `variant="embed"` 사용
- 마쓰야마처럼 현재 프로모션 페이지의 제공 지역과 일치하지 않으면 억지로 삽입하지 않는다.

## 호텔·게스트하우스·단기임대 제휴 연결

1. 글에 실제 등장하는 숙소의 정확한 상품명과 위치를 정한다.
2. `products`에 안정적인 `productKey`로 등록한다.
3. 판매처와 제휴 네트워크를 분리해 `offers`에 실제 발급 URL을 등록한다.
4. `placements`에 문맥에 맞는 버튼 문구와 설명을 등록한다.
5. 글의 `affiliatePlacements`와 `<StayRecommendations>`에 placement key를 넣는다.
6. 활성 링크가 있을 때만 CTA와 제휴 고지가 표시되는지 확인한다.

에어비앤비 등 서비스별 제휴 제공 여부와 딥링크 정책은 가입 계정의 현재 공식 조건을 확인한 뒤 연결한다.

## 숙소별 딥링크는 나중에 개별 등록한다

쿠팡파트너스·익스피디아 딥링크는 숙소·장소마다 새로 발급해야 하는 경우가 많다. 딥링크를 기다리느라 글 발행을 미루지 않고, 다음 순서로 점진적으로 붙여나간다.

1. 글에 등장하는 숙소마다 `products`에 안정적인 `productKey`를 먼저 만든다.
2. `offers`에 같은 `productKey`로 `status: "planned"`, `commissioned: false`인 항목을 등록한다 (URL은 임시값이거나 비워둔다). 이 상태에서는 `StayRecommendations`의 예약 버튼이 자동으로 숨는다 — 코드나 템플릿을 손댈 필요가 없다.
3. 글은 그대로 발행한다. 정보 콘텐츠(시간표·환승·숙박 권역 판단)는 예약 링크 유무와 무관하게 가치가 있다.
4. 실제 딥링크(쿠팡파트너스 API 발급본, 익스피디아 딥링크+프로모션 코드 등)가 나오면 해당 `offers` 항목만 갱신한다: `url`, `status: "active"`, `commissioned: true`, `affiliateNetwork`("coupang-partners" | "expedia" | "direct" | "other"), `checkedAt`. 페이지·템플릿 코드는 건드리지 않는다.
5. 딥링크를 전달할 때는 `productKey + 실제 URL + (있으면) 프로모션 코드`만 알려주면 바로 등록해 반영한다. 만료 정책이 있는 딥링크는 만료 시점도 함께 알려준다.

## 글 발행 전 확인

- 제목에 지역·교통 문제·결정이 드러나는가
- 첫 문단에서 질문에 바로 답했는가
- 시간표·운임·운영 정보에 공식 출처와 확인일이 있는가
- 호텔명보다 숙박 권역의 선택 기준을 먼저 설명했는가
- 직접 이용하지 않은 경험을 꾸미지 않았는가
- 현재 지역과 정확히 일치하는 오퍼만 연결했는가
- 이미지가 모두 WebP이며 출처와 사용권을 확인했는가
- 모바일 표와 긴 제목이 읽히는가
- `npm run build`가 통과하는가
